# Testing

`bin/hermes-eos-verify` is the PAG-1 acceptance command. It runs:


- Phase 0 backup checksum verification;
- vendor provenance, license, dependency, and forbidden-runtime checks;
- credential-scrubbed plugin import/register qualification with fake sync and
  async LLMs;
- Python adapter, read-only SQLite, namespace, redaction, GitHub fixture,
  GET-only route, and `phase3-v1` golden outcome tests;
- TypeScript checking and deterministic esbuild output;
- Node tests for event coalescing, status transition deduplication/replay, SDK
  registration, IIFE format, host React use, and token guards;
- isolated Chromium navigation/API-failure tests;
- installed dashboard Chromium navigation across all views including
  Analytics, Evaluations, Performance, Experiments, and Adaptation;
- live authenticated API and static asset checks;
- exact production Git and gateway boundary comparisons;
- normalized Docker identity excluding new `hermes-eos-*` containers;
- storage ≥20 GiB free and used < 80%;
- live Phase 6 experiment data quality (`scripts/verification/verify-experiment-data.sh`);
- live Phase 7 adaptation data quality (`scripts/verification/verify-adaptation-data.sh`);
- PAG-1 data-quality and chaos-safe branches (`scripts/verification/verify-pag1-data.sh`);
- PAG-1 unit tests for operator-boundary output, approval bindings, budget
  gate, all five real-v1 evaluators, and independent readiness cells.
- PAG-2 unit tests (`tests/python/test_pag2.py`) for confirmatory freeze,
  SO_PEERCRED reject, OS IPC timeout, atomic reservation, HARD budget
  argv/timeout, protected-trust caller-key ignore, live patch hash,
  deploy-tool ubuntu install reject, Phase-4 primary outcome, pag2 labels,
  fail-closed shadow/canary/rollback, H2 write-budget gates, unsigned
  Approval A reject, shadow scope no exposure consume, H3 live-patch
  identity sync, hermes-op-only canary bind, IPC probe without a
  confirmatory candidate, AUTH_NO_PROTECTED_VERIFIER_SCRIPT, and
  AUTH_NO_PROTECTED_PLUGIN_SOURCE;
- PAG-2 hardening script `scripts/verification/verify-pag2-hardening.sh`.
- PAG-2 gate dashboard `scripts/deployment/pag2-status.sh` (read-only).

Additional observability scripts: `scripts/observability/otel-smoke-test.sh`,
`scripts/observability/otel-fail-open-test.sh`, `scripts/observability/otel-privacy-test.sh`,
`scripts/observability/otel-phoenix-e2e.py`, `scripts/observability/otel-persist.py`.

Additional evaluation scripts: `scripts/evaluation/evaluation-fail-open-test.sh`,
`scripts/evaluation/evaluation-privacy-test.sh`, `scripts/evaluation/evaluation-sandbox-test.sh`,
`scripts/evaluation/evaluation-canary.sh`, `scripts/verification/verify-evaluation-data.sh`.

Additional performance scripts: `scripts/observability/performance-fail-open-test.sh`,
`scripts/observability/performance-privacy-test.sh`, `scripts/verification/verify-performance-data.sh`,
`scripts/observability/performance-materialize.sh`.

Additional adaptation scripts: `scripts/adaptation/adaptation-fail-open-test.sh`,
`scripts/adaptation/adaptation-privacy-test.sh`, `scripts/verification/verify-adaptation-data.sh`,
`scripts/adaptation/adapt.sh`, `scripts/adaptation/adaptation-materialize.sh`.

Writable Git tests use only `.runtime/fixture-repo`, generated by
`scripts/maintenance/create-fixture-repo.sh`. Tests do not write the canonical Kanban
database, production repositories, Hermes source, or its virtual environment.

Browser binaries and output remain ignored under `.cache/` and
`dashboard/test-results/`.
